# 포켓몬 상태창 동양판 배치 이식 계획

## 기준과 확인 결과 (2026-10-10)

참조는 작업 공간의 `original-gold`이다. 해당 폴더의 `pokegold.gbc` SHA-1은
`c0ff3999e1093e1af59ef3eea3f1bfd7c1f18a65`로 README의 한국판 금 기준과 일치한다.
상태창 ASM에서 세로 구분선 x=7, 왼쪽 개체 정보와 오른쪽 페이지 정보가 확인된다.
이는 사용자가 제시한 동양판 화면과 일치한다. 일본판 크리스탈과의 동일성은 주장하지 않는다.

| 요소 | 현재 Crystal | original-gold 동양판 |

| 구분선 | 가로 y=7 | 세로 x=7 |
| 번호 | (8,0) | (1,0) |
| 포켓몬 그림 | (0,0) | (0,1) |
| 레벨 / 성별 | (14,0) / (18,0) | (1,8) / (5,8) |

좌표는 타일 단위이며 한글 출력 좌표는 글자의 아래쪽 타일이다.

## 이식 범위와 Crystal에 필요한 조정

1. Crystal의 상태창 상태 머신, 모바일 처리, 파티/박스/임시 포켓몬 접근,
   이름 디코더, 울음소리와 애니메이션을 유지하며 그리기 루틴을 변경한다.
2. 기본 구조는 위 한국판 금 배치로 바꾸고 CGB 팔레트 영역과 SGB 그림 영역도 맞춘다.
3. 사용자는 후속 지시로 영문 이름의 폭 대응을 제외하고 전면 한글화를 목표로 정했다.
   한글 5자 이름 기준으로 닉네임 (1,10), 종 이름 (1,12), 페이지 사각형 y=14와
   안내 y=16을 참조판에 맞춘다. 이름 저장 형식은 유지한다.
4. OT 이름도 기존 한글 이름 디코더로 참조판 (12,3)에 출력한다.
5. 기술/타입은 이미 Crystal 안에 있는 한글 표를 활용한다. 상태창 전용 상태·능력치
   라벨은 금 소스를 참고해 작성한다. 공용 전투 상태 약어는 이번 범위에서 변경하지 않는다.
6. 소지품은 금의 한국어 이름을 Crystal 소유의 상태창 전용 표로 이식한다.
   아이템 ID 배열을 비교하고, 다른 화면의 공용 이름 표는 기존 동작을 유지한다.
   참조판의 ITEM_81은 Crystal의 EGG_TICKET이므로 실제 항목에 맞춰 알티켓으로 표기한다.
   이름은 참조판 (12,2)에 출력한다. 가장 긴 항목도 8칸으로 화면 안에 들어간다.
7. 페이지 안내는 참조판의 4타일 그래픽을 Crystal 안의 ASM 데이터로 보관한다.
   빌드에는 Crystal의 폰트/창/HP/경험치 그래픽을 사용한다.
8. 빈 기술/PP 표시와 알 화면도 같은 배치로 점검한다.
9. 긴 한글 기술 4개에 이름·소지품·고정 라벨이 함께 표시되면 54칸 폰트 캐시가
   빠듯해질 수 있다. 고정 제목 `사용할수 있는기술`은 Crystal의 기존 폰트에서
   조립한 18타일을 빈 $42~$53 구간에 올린다. 동적 이름·기술의 캐시 공간을 확보하며
   스프라이트 $00~$30, 페이지 타일 $31~$41, 경험치 바 $55~$5c와 겹치지 않는다.

## 종속성 정책

`original-gold`는 조사·비교용이다. Crystal의 INCLUDE/INCBIN/Makefile/도구에
부모 폴더 경로, 참조판 ROM, 참조판 생성물을 추가하지 않는다.
필요한 문자열과 그래픽은 Crystal 내부의 추적 가능한 소스 파일로 보관한다.
SRAM/WRAM 정의와 ROM0 코드는 이 작업에서 늘리지 않는다.

## 위험과 검증

- 한글이 두 타일 높이이므로 라벨·값·프레임·다음 줄 사이의 중첩을 확인한다.
- 페이지를 지울 때 오른쪽 전체만 지워 왼쪽 이름/그림/페이지 안내를 보존한다.
- 그림 위치가 바뀌는 모든 알 애니메이션 진입점도 함께 옮긴다.
- 일반/디버그를 조립·링크·후처리해 배치와 체크섬을 확인한다.
- 아이템 ID 및 한글 표의 폭, 외부 경로 참조, 기존 RAM 주소를 정적으로 확인한다.
- 사용자 실행 확인: 세 페이지, 좌우/A/B/상하 이동, 한글 5자 이름,
  단일/복합 타입, 정상/기절/상태 이상, HP 0/전체, 최대 레벨, 소지품 유무,
  기술 1~4개, 박스 포켓몬과 알, 화면 종료 후 전투/메뉴 복귀.
- 빌드 통과와 실제 화면·애니메이션 검증은 별도로 기록한다.

## 착수 판단

참조판의 세로 구조와 기준 ROM 해시가 확인됐고, 한글 이름 폭과 Crystal 고유 경로를
보존하는 이식 방법을 정했다. 위 범위로 구현을 시작한다.

## 구현 및 정적 검증 결과

- 세로 구분선, 그림·번호·레벨·성별·닉네임·종 이름, 페이지 표시,
  세 페이지 프레임 및 출력 좌표를 한국판 금 소스 기준으로 변경했다.
- 일반 포켓몬·안농·알 그림의 진입점과 알 애니메이션 좌표를 (0,1)로 맞췄다.
  상태 머신·모바일 처리·파티/박스 데이터 접근은 Crystal 흐름을 유지한다.
- 타입과 기술은 기존 Crystal 내부 한글 표를 재사용한다.
  255개의 상태창 소지품 이름을 내부 표에 보관했고 최대 폭 8칸을 확인했다.
  EGG_TICKET은 알티켓으로 표기한다. 251개 기술 이름도 프레임 폭 10칸 안에 들어간다.
- 채택한 모든 알 설명 줄은 오른쪽 12칸 안에 들어간다.
- 빈 PP를 텍스트 경로로 표시하고, 기술 0개일 때 PP 루프가 256번 돌지 않도록 처리했다.
  전투·파티의 공용 기절 약어는 이번 상태창 전용 기절 라벨과 별도로 유지한다.
- 고정 기술 제목 144바이트는 최종 ROM에서 현재 charmap과 로컬 한글 폰트로
  계산한 글리프와 일치했다. 페이지 안내 64바이트도 참조판의 4타일과 일치했다.
- 일반·디버그 각각 18개 객체를 모두 재조립하고 링크·RGBFIX·Stadium 후처리를 통과했다.
  기존 생성 그래픽을 사용했으며 전체 clean make를 수행한 결과는 아니다.
- 두 빌드의 실제 RGBASM 의존 파일 5,920개를 검사했다. 모두 Crystal 내부에 존재하고,
  외부 참조는 0개다. 한글 폰트와 기존 상태창 그래픽의 PNG도 Crystal Git 추적 소스다.
- 기존 일반 빌드와 비교한 RAM 심볼 14,413개의 주소/은행은 모두 동일하다.
  ROM0 잔여량도 일반 60바이트, 디버그 67바이트로 유지된다.
- 최종 헤더·전체 체크섬 검사가 두 ROM 모두 통과했다.
  기존 배포 ROM과 세이브를 덮어쓰지 않고 별도 검사용 파일을 생성했다.
- 기존 `data/text/std_text.asm:155`의 unmapped `~` 경고는 남아 있다.
  이번 상태창 이식에서 새로 발생한 인코딩 경고는 없다.

## 실행 확인은 아직 남아 있음

에뮬레이터 화면을 직접 검증한 결과는 아직 없다. 다음 순서로 사용자 실행 확인을 진행한다.

1. 한글 기본 이름/5자 닉네임으로 분홍 → 초록 → 파랑 → 분홍 페이지를 돌고
   상하로 포켓몬을 바꾼다. 왼쪽 이름·그림·페이지 표시가 유지되는지 본다.
2. 소지품 유무, 한 개/네 개 기술, 긴 한글 기술 이름, 빈 기술/PP의 대시,
   단일/복합 타입과 기절·상태 이상 표시를 확인한다.
3. 알과 박스 포켓몬에서도 이동·A/B 종료를 확인하고, 상태창을 닫은 후
   파티/전투 화면의 이름과 글자가 정상인지 확인한다.

일반·디버그를 함께 생성하려면 현재 Makefile에서
`make RGBDS=rgbds-1.0.0/ crystal crystal_debug`를 실행할 수 있다.
기본 `all` 대상 자동 변경은 사용자가 나중에 하기로 했으므로 이번 범위에는 포함하지 않았다.
