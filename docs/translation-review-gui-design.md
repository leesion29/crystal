# oldgold 대사 이식 검수기 설계

## 목적

`oldgold`의 한글 대사를 `crystal`에 이식할 때, 파일 전체를 복사하거나
문자열 검색으로 위치를 찾지 않고 **라벨 단위로 비교·검수·승인**한다.

자동화의 역할은 후보 수집과 안전 검사까지다. 번역문을 실제 소스에 반영하는
결정은 사용자가 한다.

## 범위

첫 구현 범위는 다음으로 제한한다.

- 입력: `oldgold`, `crystal`의 `maps/**/*.asm`, `data/text/**/*.asm`
- 단위: `Label:`로 시작하는 텍스트 블록
- 인식 명령: `text`, `line`, `para`, `cont`, `done` 및 텍스트 내 제어 토큰
- UI: Python 표준 라이브러리 `tkinter`

맵 이벤트, 오브젝트, 이동 스크립트, 그래픽, 바이트코드 및 라벨 추가·삭제는
첫 구현의 대상이 아니다.

## 핵심 원칙

1. 같은 상대 경로와 같은 라벨끼리만 비교한다.
2. `oldgold`에 한글이 있고 `crystal` 대상에 한글이 없을 때만 자동 이식 후보로 삼는다.
3. `crystal`에 이미 한글이 있으면 기본적으로 잠근다. 명시적인 해제 없이는 덮어쓰지 않는다.
4. 한쪽에만 있는 라벨은 추가·삭제하지 않는다.
5. 제어 토큰 또는 조건부 구조가 다르면 자동 적용하지 않고 검토 대상으로 올린다.
6. 실제 쓰기는 사용자가 확인한 항목에 한하며, 적용 전 diff를 반드시 보여 준다.

## 화면 구성

```text
파일 목록                  oldgold 원문             crystal 대상
maps/ElmsLab.asm (51)      ElmAfterTheftText5       ElmAfterTheftText5
data/text/common_1.asm      text / line / para       text / line / para

상태: 구조 차이 경고
토큰: <PLAYER> 일치 / text_ram 일치 / 조건문 차이

[이식 승인] [건너뛰기] [검토 완료] [다음 후보]

선택 항목 diff 미리보기
[승인 항목만 적용]
```

### 파일 목록

각 파일에 다음 개수를 표시한다.

- 안전 후보: 자동 이식 가능한 미번역 공통 라벨
- 잠김: 이미 한글인 crystal 라벨
- 검토 필요: 토큰 또는 구조가 달라 자동 이식이 차단된 라벨
- 전용: 한쪽에만 존재하는 라벨

### 라벨 비교 창

원문과 대상을 나란히 보이고, 줄 단위 diff와 다음 정보를 함께 표시한다.

- 라벨명과 소스 경로
- 텍스트 명령 목록
- 제어 토큰 목록: 예) `<PLAYER>`, `<PLAY_G>`, `<RIVAL>`, `text_ram`, `text_decimal`
- 조건부 블록: 예) `if !DEF(_DEBUG)` / `endc`
- 상태 및 차단 사유

## 상태 분류

| 상태 | 조건 | 기본 동작 |
| --- | --- | --- |
| 안전 후보 | 공통 라벨, oldgold 한글, crystal 비한글, 구조·필수 토큰 일치 | 일괄 또는 개별 승인 가능 |
| 잠김 | crystal에 한글 포함 | 변경 불가 |
| 구조 검토 | 조건문, 텍스트 명령, 필수 토큰이 다름 | 개별 확인 전 적용 불가 |
| oldgold 전용 | crystal에 같은 라벨 없음 | 표시만 함 |
| crystal 전용 | oldgold에 같은 라벨 없음 | 표시만 함 |

`<PLAYER>군`처럼 일반 텍스트에 포함된 호칭과 `<PLAY_G>` 같은 제어 토큰은
서로 다른 것으로 표시한다. 자동 치환하지 않는다.

## 적용 방식

1. 사용자가 후보를 승인한다.
2. 도구는 승인 목록의 변경 전후 diff를 생성한다.
3. 사용자가 `승인 항목만 적용`을 눌러야 파일에 쓴다.
4. 적용 대상은 해당 라벨의 텍스트 본문뿐이다. 라벨명과 인접한 맵 스크립트는 유지한다.
5. 적용 직후 다시 스캔해 결과 요약을 표시한다.

조건문이 있는 텍스트는 기존 crystal의 조건문 경계를 유지하는 별도 적용 모드를
나중에 제공할 수 있다. 첫 구현에서는 자동 적용하지 않는다.

## 기록과 복구

도구는 저장소의 `.translation-review/` 아래에 다음만 기록한다.

- 승인·건너뜀·검토 완료 상태
- oldgold/crystal 파일 해시
- 라벨명, 적용 시각, 적용 전후 텍스트 해시
- 적용 직전의 unified diff

원본 `oldgold`는 읽기 전용으로 취급한다. 작업 중인 crystal 파일에 기존 미커밋
변경이 있으면 해당 파일을 경고로 표시하며, 자동 일괄 적용에서 제외한다.

## 단계별 구현

### 1단계: 파서와 검사기

- ASM 파일에서 라벨과 텍스트 블록을 추출한다.
- 상대 경로·라벨 기준으로 비교한다.
- 한글 여부, 제어 토큰, 조건문 차이를 판정한다.
- 결과를 JSON과 콘솔 목록으로 출력한다.

### 2단계: 읽기 전용 GUI

- 파일 목록, 상태 필터, 원문·대상 비교, diff 표시를 제공한다.
- 이 단계에서는 파일을 수정하지 않는다.

### 3단계: 승인과 적용

- 승인 목록을 저장한다.
- 수정 전 diff를 표시한다.
- 승인된 안전 후보만 적용한다.
- 적용 기록과 재스캔 결과를 남긴다.

### 4단계: 보조 기능

- 빌드 로그에서 은행 초과 오류를 읽어 섹션·초과 바이트를 표시한다.
- `pokecrystal.map`과 `layout.link`를 분석해 후보 배치 은행의 여유 공간을 제안한다.

## 검증 기준

- 기존 한글 라벨을 자동으로 바꾸지 않는다.
- crystal 전용 라벨을 추가·삭제·덮어쓰지 않는다.
- 필수 제어 토큰이 다른 항목은 자동 적용되지 않는다.
- 적용 diff가 승인 목록과 정확히 일치한다.
- 적용 후 ASM 빌드가 정상 완료되어야 한다.

## 선행 조건

현재 환경에서는 `python` 또는 `py` 명령이 확인되지 않았다. 구현 전에는 Python
실행 환경과 `tkinter` 사용 가능 여부를 확인한다. 별도 GUI 프레임워크는 첫 구현에
사용하지 않는다.
