# 가방 목록 한글 윗줄 잔상

작성일: 2026-10-11

## 증상과 원인

사용자가 제공한 `Downloads/1.png`, `Downloads/2.png`에서는 기술머신 목록을 빠르게 넘길 때 첫 기술 이름의 윗부분이 남는다. 이미지의 입력 시점과 프레임은 확인되지 않았으므로 정확한 PPU 타이밍 문제까지 확정하지는 않는다.

코드에서 확인된 지우기 범위 누락은 다음과 같다.

- `engine/hangul/text.asm:_PlaceHangul`은 기준 좌표에 하단 타일, 그 한 행 위에 상단 타일을 쓴다.
- `engine/items/tmhm.asm:TMHM_DisplayPocketItems`의 이름 기준 행은 2·4·6·8·10행이다. 따라서 첫 이름 상단은 1행이다.
- 기존 지우기는 (5,2)에서 너비 15·높이 10, 즉 2~11행만 지운다. 이름이 짧아지거나 CANCEL·빈 영역으로 바뀌어 상단 타일이 다시 쓰이지 않으면 1행에 이전 이름 상단이 남는다.
- `engine/items/pack.asm:ClearPocketList`도 포켓 전환 때 같은 누락이 발생할 수 있는 지우기 범위를 사용했다.
- 일반 도구·중요한 도구·볼 목록의 `ScrollingMenu_UpdateDisplay`는 `ClearWholeMenuBox`를 사용해 메뉴 상단 1행부터 이미 지우므로 변경하지 않았다.

## 채택한 계획과 수정

위 두 가방 전용 지우기의 시작 행을 2에서 1로, 높이를 10에서 11로 변경했다. 결과는 x=5~19, y=1~11이다. 아래쪽 경계는 기존과 같고, 탭이 있는 0행·왼쪽 아이콘 x=0~4·설명 상자 y>=12는 보존한다. 글꼴·캐시·문자열·입력·게임 로직은 변경하지 않는다. 공용 메뉴 지우기를 확대하는 것은 다른 메뉴까지 영향을 주므로 선택하지 않았다.

## 검증 범위

- 일반·디버그 빌드 성공.
- `tools/verify_pack_clear.py`: 최종 ROM의 실제 `ClearBox`와 두 호출 경로를 실행해 정확한 지우기 범위, 타일맵 경계·주변 UI 보존, 192개의 긴 이름→짧은 이름→빈 영역 전환을 검사한다. 이름의 타일 배치는 시드로 주입하며 실제 글꼴 그리기·PPU는 실행하지 않는다. 기술머신 경로는 지우기가 끝난 뒤 항목 조회 직전에 중단한다.
- 일반 스크롤 메뉴의 기존 지우기 범위도 실행해 확인한다. 두 경로를 기존 시작 행·높이로 되돌린 변이는 상단 잔상 검사에서 실패해야 한다.
- 기존 기술머신·이름/캐시, 아이템, START 메뉴, ROM 헤더·뱅크·스프라이트 검증도 일반·디버그 ROM에서 실행한다.
- 검사 도구의 제한된 CPU에 이번 경로에서 사용하는 조건부 JP 및 레지스터 SUB 명령 처리를 추가했다. 게임 코드 변경이 아니다.

빌드에는 기존 `data/text/std_text.asm:155`의 미매핑 `~` 경고가 남아 있다. 가방 수정 범위 밖이라 변경하지 않았으며, 오류 없는 빌드 성공과 별개인 인코딩 문제다.

코드에서 누락과 수정 범위는 확인했으나 에뮬레이터의 빠른 스크롤·포켓 전환 재현은 수행하지 않았다. 실제 화면 증상의 최종 해결 여부는 아직 런타임 검증 전이다.
