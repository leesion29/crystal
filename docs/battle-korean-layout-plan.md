# 전투 화면 한글 골드 배치 이식·수정 계획

## 2026-10-07 수정 계획 — 실제 골드 비교 화면 기준

사용자의 추가 이미지에서 왼쪽 골드는 굵은 L자 HP 테두리와 `:L` 표기를 사용한다.
앞선 OldGold 기반의 빈 테두리/Lv 이식은 이 외형 기준과 다르므로 철회한다.
`gold`와 `oldgold` 폴더의 두 HP 테두리 그래픽은 바이트가 동일하며 모두 개조된 형태다.
따라서 폴더 이름만으로 정발 외형을 판단하지 않고, 첨부 화면과 일치하는 Crystal의
기존 HP 테두리와 레벨 타일을 사용한다. 이름 테이블 기준(OldGold)은 바꾸지 않는다.

### 수리 순서

1. 전투 로더의 빈 테두리/Lv 덮어쓰기를 제거한다. 기존 공용 원본 그래픽은 이미
   보존되어 있으므로 이를 다시 로드하면 적/아군의 굵은 테두리와 `:L`가 복원된다.
2. 사용하지 않게 된 전투 전용 빈/Lv 데이터를 제거한다.
3. 한글 이름·성별·레벨 배치와 한글 메뉴는 유지한다.
4. `_ReturnToBattle_UseBall`의 CloseWindow 바로 뒤에서 HUD를 다시 그린다.
   이 함수는 메뉴 진입 전에 저장했던 타일 번호를 복원한다. 메뉴 렌더링 중에는
   화면에 없는 이전 이름의 캐시 타일이 재사용될 수 있으므로 번호만 복원해서는
   이름 그래픽까지 복원되지 않는다. 원본 레코드를 다시 렌더링하는 경계를 추가한다.
   포획 시범은 주인공 포켓몬 대신 트레이너 그림이 나오므로 적 HUD만 갱신한다.
5. 변경 범위와 미사용 참조를 정적으로 확인한다. 사용자 빌드 후 평상시 전투와
   몬스터볼 사용 직전/직후, 포획 성공/실패 화면에서 이름·HP창을 확인한다.

이름 깨짐은 위 경로에서 발생 가능한 코드 원인으로 확인했으며, 첨부 화면의 실제
캐시 상태는 관측하지 않았다. 실행 검증 전 모든 경로의 해결 완료로 단정하지 않는다.

아래는 앞선 구현의 기록이며, 빈 테두리/Lv 관련 결정은 위 수정 계획으로 대체한다.

### 수정 결과

- 빈 테두리/Lv 덮어쓰기 및 전용 데이터를 제거했다. load_font.asm과 gfx/font.asm은
  이 작업 전 Git 기준과 동일한 상태로 돌아왔으며 원본 그래픽 파일은 변경하지 않았다.
- 볼 사용 복귀 지점에 일반 전투 양쪽 HUD / 포획 시범 적 HUD 재출력을 추가했다.
- Gold/OldGold의 두 그래픽 파일 SHA-256 동일성을 확인했다.
- 한글 메뉴·이름 배치, 기존 대사·RAM·상수는 그대로 유지했다.
- 정적 차이 검사는 통과했으며, 빌드·에뮬레이터 화면 검증은 아직 수행하지 않았다.

2026-10-07. 기준: `oldgold/engine/battle/{core,menu,trainer_huds}.asm` 및
`oldgold/gfx/battle/{enemy_hp_bar_border,hp_exp_bar_border}.2bpp`.

## 범위와 보호 조건

- 일반 전투의 이름/성별/레벨·상태, HP창 외형, 4개 명령을 한글판 기준으로 맞춘다.
- 벌레잡기 대회의 메뉴도 대응하는 OldGold 문구와 배치를 사용한다.
- 기존 번역 대사, 전투 계산, HP/경험치 계산, 몬스터 상수, 저장 형식 및 RAM 배치는 변경하지 않는다.
- 크리스탈 고유 모바일 전투와 미사용 사파리 메뉴는 유지한다. 공용 메뉴 렌더러도 변경하지 않는다.
- 모든 ROM 빌드와 에뮬레이터 검증은 사용자가 수행한다. 정적 확인과 실행 검증을 구분한다.

## 확인된 원인과 차이

1. 현재 적 이름은 `(1,0)`에 출력된다. 한글은 기준행 위에도 쓰므로 화면 밖으로 나간다.
   OldGold는 적 `(2,1)`, 아군 `(10,8)`에서 이름을 정렬하고 뒤에 성별·레벨을 붙인다.
2. OldGold는 3글자 이하 +2칸, 4글자 +1칸, 5글자 이상 +0칸으로 이름을 배치한다.
   현재 저장된 이름은 packed/legacy 두 형식이므로 바이트 수가 아니라 논리 글자 수로 센다.
3. OldGold의 테두리 배치 코드는 크리스탈과 같지만 해당 그래픽은 대부분 빈 타일이다.
   OldGold 2bpp의 양 plane이 동일하므로 필요한 타일은 1bpp로 정확히 표현할 수 있다.
   전투 로더에서만 덮어쓰고 능력치/파티 화면이 쓰는 공용 원본은 유지한다.
4. 크리스탈 메뉴의 내부 선택 번호는 2=포켓몬, 3=가방이다. 한글판은 표시 위치가 반대다.
   입출력 경계에서 2↔3을 변환하여 전투 분기·모바일 기능을 보존한다.
   포획 시범의 가방 자동 선택은 아래+A 대신 오른쪽+A로 바꾸되 기존 대기 시간을 유지한다.
5. 캐시 타일 번호로 마지막 글자를 비교하면 니드런♂/♀의 성별 기호를 판별할 수 없다.
   원본 레코드의 마지막 논리 글자를 확인해 중복 기호를 방지한다.

## 구현 순서

1. 이름 레코드를 NAME_LENGTH 이내에서 읽는 전투 전용 배치 보조 루틴을 추가한다.
   한글 최대 5글자는 한 줄 HUD를 사용한다. 7글자 이상인 기존 영문 이름은 자르지 않고
   이름/성별·레벨을 두 행으로 나눠 화면 폭을 지킨다.
2. 이름 끝 좌표를 DVs/성별 호출 전후에 보존한다. 상태 약어는 기존 영어를 유지하되
   동적 폰트 캐시를 거치는 PlaceString으로 출력한다. 레벨 100 처리도 기존 PrintLevel을 유지한다.
3. 전투 전용 로더에서 테두리를 비우고 OldGold의 Lv 타일을 공급한다.
4. 정상/대회 메뉴 문구·간격을 이식하고 선택 번호 변환을 연결한다.
5. 차이와 좌표/스택/선택 번호를 정적 점검한다. 빌드 후 사용자 화면 검증을 받는다.

## 사용자 검증 체크리스트

- 야생/트레이너 전투: 적 이름 윗부분, 아군 이름, HP 숫자·HP바·경험치바.
- 한글 2·3·4·5글자 이름, 니드런♂/♀, 성별 없는 포켓몬, 긴 영문 닉네임.
- 레벨 1·99·100, 독/화상/마비/얼음/수면, 변신, 교체·가방에서 돌아온 화면.
- 4개 메뉴 각각의 실제 동작, 마지막 선택 위치, 포획 시범에서 가방→몬스터볼 자동 선택.
- 벌레잡기 대회 메뉴와 파크볼 잔량, 능력치/파티 화면의 공용 그래픽 회귀 여부.
- 모바일 경로는 별도 유지 대상이며 실행 검증 전 호환 완료를 주장하지 않는다.

## 상태

위 범위 구현 완료. 실행 검증은 미완료이며 배포 완료를 뜻하지 않는다.

### 정적 점검 결과

- OldGold 이름 테이블의 모든 이름 + 성별 1칸 + 레벨/상태 최대 3칸: 지정 HUD 폭 이내.
- 메뉴 1~4 선택 번호의 2↔3 왕복 변환: 원래 내부 번호로 복원됨.
- 새 메뉴의 모든 한글: includes.asm이 사용하는 두 한글 charmap에 매핑 존재.
- OldGold 테두리 원본: 모두 0. Lv 타일: 2bpp 양 plane과 추가한 1bpp 8행이 정확히 일치.
- 공용 HP/경험치 원본 파일, RAM 정의, 대사 파일: 이번 작업에서 변경하지 않음.
- git diff --check 통과. 어셈블/링크·뱅크 용량·에뮬레이터 출력은 사용자 빌드 후 확인 필요.

대회 파크볼 잔량은 변경된 파크볼 항목 위치에 맞춰 `(17,14)`로 옮겼다.
미사용 사파리 메뉴는 새 선택 번호 변환을 거치지 않는다.
전역 프레임 설정과 프레임 이미지, HP 색상은 유지한다. 스크린샷의 테두리 무늬까지
동일하게 맞추는 것은 이번 텍스트/HUD 배치 이식과 별도다.
