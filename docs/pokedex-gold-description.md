# 골드 한글 도감 설명 이식

## 결정

- 사용자가 크리스탈 고유 설명 대신 골드의 기존 한글 설명 사용을 승인했다.
- oldgold의 251개 대응 파일에서 분류와 설명을 그대로 가져온다. 번역 문장은 수정하지 않는다.
- 이미 적용된 dm/hg 키·무게 값은 유지한다. 종 상수·순서·세이브 형식은 변경하지 않는다.
- 설명은 한 페이지, 세 줄이다. PAGE와 P.1/P.2 표시는 제거한다.

## 배치와 렌더링

- 이름 (9,2), 분류 (9,4)에 `포켓몬`을 덧붙인다. 분류 최장 5칸 + 접미사 3칸.
- 키 6행, 무게 8행, 설명 구분선 9행.
- 설명 시작 (1,11), 줄 기준선 11/13/15행. 한글 상단 타일까지 포함해 10~15행을 지운다.
- 설명 폭 18칸을 확보하며 원문의 줄바꿈도 유지한다.
- 후속 사용자 승인으로 도감 PRNT 항목과 진입 경로를 제거한다. 다른 화면의 인쇄 기능은 유지한다.
- 하단 메뉴는 `분포 / 울음소리` 두 항목이다. 사용자가 만든 `dex_text.png`를 그대로 `gfx/pokedex/entry_menu.png`에 복사했다. SHA256은 `9b430234fd9abb5c28850d47c2bf802d78286da8cdc401504090ffaf2895fe74`이다. 원본은 변경하지 않는다.
- PNG는 48x16, 불투명 흑백이며 상단 8픽셀은 검정, 하단 8픽셀에 글씨가 있다. 왼쪽 16픽셀은 분포, 오른쪽 32픽셀은 울음소리다. 내부 간격을 포함해 모든 픽셀을 보존한다.
- 기존 Makefile의 PNG→2bpp 규칙(`rgbgfx --colors dmg`, 기본 행 우선 배열)으로 변환한다. 12타일/192바이트를 $6d~$78에 직접 복사하며, 흰 글씨·검은 배경 원본이므로 반전하지 않는다. 크기 assert를 둔다. 동적 한글 캐시는 쓰지 않는다.
- 사용자 화면 검증 후 메뉴 바를 오른쪽 8픽셀, 위쪽 1픽셀 조정했다. 끝은 x=3/17, 분포 x=5~6, 울음소리 x=12~15, 커서 (4,17)/(11,17)이다. SCX=5를 반영한 화면상 바 범위는 [19,139), 중심은 79픽셀로 화면 중심 80픽셀과 1픽셀 차이다. 문구 사이 간격은 유지한다.
- PNG 로드 뒤 LCD-off 상태에서 표시 타일을 변환한다. 글씨 하단 6타일은 $6f~$74로 한 줄 올리고, 첫 픽셀 행은 16행의 테두리 타일 하단에 이어 붙인다. 테두리의 위 7픽셀은 그대로 보존한다. 상단은 서로 다른 4패턴($6b~$6e)을 쓴다. 현재 원본의 두 번째 타일 첫 행은 비어 있고 세 번째/네 번째 첫 행은 같음을 정적으로 확인했다. PNG를 다시 그릴 경우 이 공유 조건도 다시 검증해야 한다.
- $75/$76은 기존 $3b/$3c를 한 줄 올린 바 양끝, $77은 바 공백, $78은 7픽셀 높이로 맞춘 커서다. 모두 마지막 픽셀 행을 $32의 프레임 배경으로 채운다. 커서는 원본 첫 두 행의 흰 픽셀을 합쳐 끝부분을 보존한다. 상세 화면에서만 커서/공백 전용 타일을 사용하며 다른 메뉴의 커서는 유지한다. 설명 10~15행은 변경하지 않는다.
- 오른쪽 잔여 조각은 `DrawDexEntryScreenRightEdge`가 BG 20열의 17행에 남겨 둔 $3c였다. 가로 스크롤로 노출되는 이 추가 열의 하단도 $32 배경으로 바꾼다.
- 후속 화면에서 글씨 첫 행 뒤에만 검은 배경이 올라가 바가 계단처럼 보이는 것을 확인했다. 16행 x=4~16의 공백·커서 칸까지 검정을 한 픽셀 확장한다. 양끝 x=3/17의 첫 행은 원래 프레임색이므로 기존 둥근 모양을 유지한다. PNG, 글씨 위치, 하단 메뉴 타일과 입력 처리는 변경하지 않는다.
- 추가 상단 공백 타일은 $6a를 상세 화면에서만 재사용한다. 이 타일의 원래 소비자는 검색 결과 화면의 모서리(8,10)이다. 상세 화면 그리기 때 `Request2bpp`로 상단 공백을 넣고, 검색 결과 화면 그리기 때 원래 모서리를 복원한다. 두 화면의 모든 재그리기에서 변환하며 일반/SGB의 모서리 16바이트와 테두리 위 14바이트는 동일함을 검사한다. 상세→검색 결과→상세 왕복 검증이 추가로 필요하다.
- 전용 타일 $6b~$78은 한글 캐시 $80~$eb 밖이고, 도감/SGB 그래픽 $31~$6a 및 발자국 $62~$65와 겹치지 않는다.
- 전용 타일은 LCD가 꺼진 도감 초기 로드 때 넣는다. 일반/SGB 그림을 각각 로드한 뒤 같은 공용 메뉴 로더를 실행한다. 두 기존 PNG는 변경하지 않는다. 분포 화면은 이 영역을 덮지 않고 복귀 시 메뉴 타일맵을 다시 그린다.
- 한글 분류 포인터 탐색 시 escape 뒤의 두 바이트를 건너뛰어, 글리프 인덱스 $50을 종료문자로 오인하지 않게 한다.
- 사용자가 일반/SGB 도감 PNG의 옵션·검색 글씨를 한글화한 뒤, SELECT 옵션/START 검색 화면 제목의 영문 문자 코드 직접 출력은 제거했다. 메인 화면 하단 안내와 같은 $44~$47(옵션), $4b~$4e(검색)의 네 타일을 $3b/$3c 양끝 사이에 표시한다. 두 제목은 (0,1), 6타일 폭이며 동적 한글 캐시를 사용하지 않는다. 본문 문구와 그림 픽셀은 수정하지 않는다. 두 화면 진입·복귀와 메인 화면의 하단 안내를 확인한다.

## 연관 경로

- 포획 직후 등록: 한 번 확인하면 다음 화면으로 진행한다. 두 번째 페이지를 읽지 않는다.
- 앞 단계에서 수정한 도감 프린터 내부 루틴은 남겨 두지만, 도감 메뉴에서는 호출하지 않는다. 당시 영문 인쇄 안내용 타일은 현재 한글 메뉴 타일로 교체했으므로, 인쇄 기능을 다시 연결하려면 안내 타일도 함께 재설계해야 한다.
- GetDexEntryPagePointer는 이전 페이지 인자에 관계없이 유일한 설명 페이지를 반환한다.

## 검증

빌드와 게임 테스트는 사용자 담당이다. 정적 검사와 실제 화면 검증을 구분한다.

- 251개 분류·설명은 oldgold 원문과 일치하며 수치 변경은 없다.
- 사용 글자의 charmap 지원 누락 0개. 설명 최대 18칸, 접미사를 포함한 분류 최대 8칸.
- 화면의 서로 다른 글자 최대 50종(스라크), 캐시 한도 54종 이내(설명 이식 당시 검사). 고정 한글 메뉴는 캐시를 사용하지 않는다.
- 도감 설명 데이터 4개 섹션의 계산 크기: 7,533 / 7,859 / 7,660 / 7,116바이트. 최종 배치와 실행 검증은 사용자 빌드 결과가 필요하다.

1. 치코리타: `잎사귀포켓몬`, 골드의 세 줄 설명, 키·무게 및 구분선 위치 확인.
2. 구구와 스라크: 긴 줄과 글자 종류가 많은 설명의 마지막 글자까지 확인.
3. 쏘콘: 가장 긴 분류 `도롱이벌레포켓몬`이 한 줄 안에 들어가는지 확인.
4. 다른 종으로 연속 이동, 분포 진입·복귀, 울음소리 작동, 도감 종료·재진입. 좌우로 두 항목만 선택되며 PRNT가 없는지 확인한다. 사용자 PNG의 간격·흑백·글자가 유지되는지, 검은 바와 커서가 한 줄에 맞는지, 16행 테두리와 설명 마지막 줄이 유지되는지 확인한다. 일반/CGB와 SGB 경로는 별도로 검증한다.
5. 새 포획 도감 등록이 빈 두 번째 페이지 없이 종료되고 닉네임 화면으로 이어지는지 확인.
6. 다른 화면의 기존 인쇄 기능은 변경하지 않았다. 도감 인쇄는 이번 사용자 선택으로 검증 범위에서 제외한다.

이 문서는 이전 `pokedex-metric-display.md`의 영문 설명·PAGE 유지 방침을 대체한다.
