# 상태창·아이콘·부화 버그 조사 및 수정 계획

작성일: 2026-10-10. 상태: **①~④ 코드 수정·정적 검증 완료 / ⑤ 별도 원인 미확정 / 사용자 실행 검증 대기**.

아래 조사 내용은 수정 전 기준이다. 2026-10-10 후속 세션에서 사용자가
② → ⑤ → ① → ③ → ④ 순서를 승인했다. 수정 결과와 최신 검증은
이 문서 마지막의 후속 작업 기록을 우선한다.

## 1. 범위와 증거 기준

- 이번 단계에서는 게임 코드, 그래픽, 세이브, 빌드 결과를 변경하지 않았다. 이 계획서만 추가한다.
- 사용자 관찰, 소스에서 확인한 결함, 실행 확인이 필요한 가설을 구분한다.
- 기술 이름 번역은 제외한다. 사용자가 수정한 `data/moves/names.asm`은 보존한다.
- 기존 작업 트리의 상태창 이식 변경도 보존한다. 관련 없는 리팩터링은 하지 않는다.
- 원인 확인 없이 알 부화 코드나 아이콘 데이터를 교체하지 않는다.
- `original-gold`와 `oldgold`는 참고 자료일 뿐이다. 구현·빌드에 외부 폴더 종속성을 추가하지 않는다.
- 중간 에뮬레이터 수동 테스트는 요구하지 않는다. 마지막에 사용자가 실행 검증한다.

### 조사 기준점

현존 ROM은 서로 생성 시점이 다르므로, 일반 ROM과 디버그 ROM을 동일한 최신 소스의 결과라고 간주하지 않는다.

## 2. 문제별 조사 결과와 수정안

### ① 상태 페이지 종료 후 배틀 잔상

**소스에서 복원 범위 누락 확인.**

호출 흐름:
`BattleMenu_PKMN → Battle_StatsScreen → BattleStatsScreenInit → 상태창 → BattleMenuPKMN_ReturnFromStats → 파티 메뉴 → 배틀 복귀`.

- `engine/battle/core.asm:5246`의 `Battle_StatsScreen`은 VRAM bank 0의 배틀 그래픽을 `vTiles0`에 백업한다.
- 저장·복원 범위는 `vTiles2 $00–$30` 및 `$31–$41`이다.
- 플레이어 뒷모습은 `$31`에서 시작하며 6×6타일이므로 `$31–$54`를 사용한다.
- 새 상태창의 `LoadGreenPage.PlaceMoveHeading`은 고정 한글 제목을 `$42–$53`에 로딩한다.
- 이 범위는 뒷모습과 겹치지만 기존 백업에는 포함되지 않는다. 배틀 복귀 시 그 타일을 사용하는 뒷모습 조각에 제목 글자가 남을 수 있다. 첨부 이미지의 글자 형태와 부합한다.
- 상태창 자체는 종료 시 타일맵을 비우며, 메뉴 복귀 경로는 `ExitMenu`/`CloseWindow`와 배틀 팔레트 복원 경로를 갖고 있다. 이번에 확인한 최초 결함은 타일맵을 지우지 않는 문제가 아니라 **타일 그래픽의 저장 범위 부족**이다.

수정안:

1. 기존 배틀 타일 백업을 `$00–$54`까지 완전하게 구성한다. 기존 보존 방식의 확장이 우선이며, 상태창에서 덮는 범위와 정확히 대응시킨다.
2. 백업 대상 `vTiles0` 공간이 상태창의 다른 writer와 겹치지 않는지 확인하고 범위 assertion을 둔다.
3. 저장·복원 중 LCD/VRAM bank 및 복귀 시 글자 캐시의 유효성을 검증한다. 실제로 깨뜨리는 경로가 없으면 캐시 초기화 등을 추가하지 않는다.
4. 대타·작아지기 상태를 포함한 기존 배틀 표시를 보존한다. 무조건 뒷모습을 다시 그리는 방식으로 대체하지 않는다.

예상 수정 파일: `engine/battle/core.asm`. 필요한 경우에만 해당 그래픽 경계 상수.

### ② 통통코 아이콘 깨짐

**아이콘 원본 손상은 확인되지 않았다. 디버그 ROM의 뱅크 배치 결함이 유력하다.**

실제 아이콘 경로는 일반 메뉴 아이콘 테이블이 아니라 개조된 팔로잉 스프라이트 경로다:
`InitPartyMenuGFX → LoadMenuMonIcon → InitPartyMenuIcon → GetIcon → FollowingSpritePointers → FarDecompress → GetGFXUnlessMobile → OAM`.

전수 정적 점검 결과:

- 포인터 278개(기본 포켓몬·알·안농 분기 포함), 대응 데이터 정의 278개를 확인했다. 누락 없음.
- 모든 원본 PNG는 16×96, 변환된 데이터는 384바이트(24타일).
- 압축 데이터 278개를 해제하여 각각의 `.2bpp`와 비교했다. **278/278 일치**, 끝 표식 이후 불필요한 바이트도 없음.
- 로더가 취하는 첫 4타일과 12타일 오프셋의 다음 4타일은 모두 데이터 범위 안이며, 완전히 비어 있는 프레임은 없다.
- 파티 슬롯당 10타일(아이콘 8+소지품 2)을 할당한다. 6마리는 `$00–$3b`, OAM은 24개로 타일 범위나 전체 40개 OAM 한도를 넘지 않는다. 이것만으로 실행 시 타일 보존까지 증명한 것은 아니다.
- 통통코 압축 바이트는 현존 일반·디버그 ROM의 심벌 주소에 모두 정확히 들어 있다.

문제의 배치:

| 대상 | 일반 ROM | 디버그 ROM |
|---|---|---|
| 통통코 팔로잉/메뉴 아이콘 | `$7f:$6048` | **`$80:$5048`** |
| 토게피 팔로잉/메뉴 아이콘 | `$7f:$550d` | **`$80:$450d`** |

디버그에서는 `PokemonSprites5` 전체가 `$80`에 배치된다. **42종**이 함께 영향을 받을 가능성이 있다:
크로뱃, 초라기, 랜턴, 피츄, 삐, 푸푸린, 토게피, 토게틱, 네이티, 네이티오,
메리프, 보송송, 전룡, 아르코, 마릴, 마릴리, 꼬지모, 왕구리, 통통코, 두코,
솜솜코, 에이팜, 해너츠, 해루미, 왕자리, 우파, 누오, 에브이, 블래키, 니로우,
야도킹, 무우마, 안농 기본 스프라이트, 마자용, 키링키, 피콘, 쏘콘, 노고치,
글라이거, 강철톤, 블루, 그랑블루. 안농 메뉴 로더는 별도의 글자별 포인터로 분기하므로 기본 스프라이트의 배치와 실제 선택 경로를 구분한다.

현재 Makefile은 MBC3+RTC+RAM 헤더를 설정한다. 일반 MBC3는 `$01–$7f` ROM 뱅크만 지원한다.
4 MiB MBC30은 별도 확장 방식이며, 단순히 파일이 4 MiB가 되었다고 모든 환경에서 지원되는 것이 아니다.
근거: [Pan Docs MBC3/MBC30](https://raw.githubusercontent.com/gbdev/pandocs/master/src/MBC3.md).
**뱅크/헤더 간 지원 범위 불일치는 확인했지만, 사용자 에뮬레이터의 실제 매퍼 선택은 확인하지 않았다. 따라서 화면 증상의 원인 확정과는 구분한다.**

수정안:

1. 일반·디버그를 같은 최신 소스로 빌드하고 ROMX 배치를 비교한다.
2. `PokemonSprites5`의 큰 단일 섹션을 필요한 만큼 분리하거나, 여유 영역에 명시적으로 배치하여 두 빌드 모두 `$7f` 이내에 넣는다. 데이터 자체와 포인터 선택 규칙은 유지한다.
3. 전체 ROMX 섹션의 지원 범위를 검증하고, 초과하면 빌드 검증이 실패하도록 한다. 통통코만 예외 처리하지 않는다.
4. 카트리지 타입을 MBC5로 바꾸거나 RTC를 버리는 수정은 하지 않는다. 현재 사용량과 여유 공간을 보면 먼저 기존 MBC3 범위 내 재배치를 검토하는 것이 타당하다.
5. 278개 자산의 포인터, 압축 결과, 목적지, 두 프레임, 소지품/메일 OAM을 최종 빌드에서 다시 점검한다.

예상 수정 파일: `gfx/following_sprites.asm`, `layout.link`, 필요한 빌드 검증 코드/문서. 공용 로더는 추가 결함이 확인된 경우에만 수정.

### ③ NO. 기호 뒷부분 깨짐

**동적 글자 캐시를 고정 글리프처럼 직접 참조하는 결함 확인.**

- `constants/charmap.asm`에서 `№ = $74`, `'.' = $e8`.
- `StatsScreen_InitUpperHalf`는 `№`와 `.`을 `ld [hl], ...`로 직접 타일맵에 기록한다.
- 한글 시스템은 `$80–$eb`를 동적 글자 캐시로 사용한다. **`$e8`은 고정 마침표 타일이 아니다.**
- 상태창 진입은 `StatsScreen_LoadFont`를 호출하지만 표준 폰트 전체를 다시 로드하거나 기존 캐시를 비우지 않는다. 이전 화면에서 `$e8`이 다른 글자로 사용되었으면 그 글리프가 표시된다.
- 일반 문자열 출력은 동적 모드에서 `PlaceCommonChar → _PlaceHangul`로 영문 기호도 올바른 캐시 타일에 연결한다. 직접 타일 기록은 이 경로를 우회한다.
- `FontBattleExtra`의 `$74`에 해당하는 `№` 데이터 및 표준 폰트의 마침표 데이터는 존재한다. 현재 근거로는 원본 비트맵을 교체할 이유가 없다.

수정안:

1. 번호 접두 기호를 기존 문자열 출력 경로로 출력해 실제 마침표 타일을 받도록 한다. 숫자의 위치와 폭은 유지한다.
2. 캐시가 이미 활성화된 경우뿐 아니라 아직 비활성인 진입에서도 기호의 수명·매핑이 안전한지 확인한다.
3. 상태창 번호·ID 접두의 다른 직접 기호 참조도 조사하되, 이번 증상과 관련 없는 전역 폰트 변경은 하지 않는다.

예상 수정 파일: `engine/pokemon/stats_screen.asm`. 폰트 파일 변경은 현재 계획에 없음.

### ④ 경험치 및 각 페이지의 흰색 배경

**프레임의 속성맵 덮어쓰기와 페이지 전환 시 속성 초기화 누락 확인.**

- 분홍·초록·파랑 페이지가 모두 공용 `Textbox`를 사용한다.
- `home/text.asm:43`의 `Textbox`는 테두리뿐 아니라 `TextboxPalette`를 호출하여 해당 직사각형을 **PAL_BG_TEXT(7), 흑백 대화창 팔레트**로 지정한다.
- `_CGB_StatsScreenHPPals`는 상태창 기본 팔레트 0, 경험치 바 2와 페이지 선택 3/4/5를 초기화한다.
- `LoadStatsScreenPals`는 페이지에 맞춰 팔레트 **0과 2의 배경색만** 바꾼다. 7의 흰색은 그대로다.
- 분홍 페이지 경험치 프레임은 `(8,10)`부터 `(19,17)`까지 팔레트 7로 덮으며 경험치 바의 기존 팔레트 2도 덮는다.
- `.ClearBox`는 오른쪽 **타일맵만** 비우고 속성맵은 비우지 않는다. 그 결과 프레임을 출력한 순서에 따라 이전 페이지의 속성이 다음 페이지에 남을 수 있다.

수정안:

1. 상태창 안의 장식 프레임은 대화창용 팔레트를 강제로 적용하지 않는 테두리 출력으로 바꾼다. 공용 `Textbox`의 전역 동작은 유지한다.
2. 페이지를 그릴 때 오른쪽 속성맵을 상태창 기본 팔레트로 재구성한다.
3. 경험치 바 팔레트 2는 분홍 페이지에서 정확한 범위에 다시 부여한다. 초록·파랑에서는 남지 않도록 한다.
4. 왼쪽 포켓몬 팔레트, HP 색, 페이지 선택 아이콘은 보존하고 속성맵 전송 시점까지 연결한다.

예상 수정 파일: `engine/pokemon/stats_screen.asm`, 필요 시 `engine/gfx/cgb_layouts.asm`. 공용 대화창 팔레트 변경은 하지 않는다.

### ⑤ 토게피 알 부화 / 부화 후 상태보기 실패

**미확정. 사용자 추가 설명을 반영해 실패 경로를 분리한다.**

사용자 관찰: 토게피 알. 디버그 기능에서는 부화되었지만 상태보기 불가. 자연 부화에서는 바로 튕김.
처음 설명의 ‘알이 깨지는 순간 정지’만으로 특정 애니메이션 함수에 원인을 배정하지 않는다.
사용한 디버그 기능이 알 상태창 START인지 다른 기능인지는 아직 확정되지 않았다.

자연 경로:
`wStepCount=$80 → DoEggStep → PLAYEREVENT_HATCH → OverworldHatchEgg → HatchEggs → EggHatch_AnimationSequence → 별명 처리 → ExitAllMenus → 맵 복귀`.

확인한 내용:

- 알 상태창 START 경로는 부화 카운터 1과 걸음 수 127을 설정한다. 이 경로를 사용했다면 다음 걸음에 일반 부화 이벤트를 실행하며, 별도 애니메이션을 즉시 실행하는 기능은 아니다.
- 부화 애니메이션은 깨짐 타일, 부화할 포켓몬 정면, 알 정면을 각각 로딩하고 흔들림·균열·껍질 조각·포켓몬 애니메이션을 실행한다.
- 토게피 정면 그래픽(`$57`), 애니메이션(`$34`), 프레임(`$36`)은 현존 디버그 ROM에서 모두 `$80` 미만이다. **토게피 정면 그림도 `$80`에 있다는 주장은 틀리다.**
- 토게피 메뉴/팔로잉 그림만 문제 ②와 동일하게 `$80`에 있다.
- `ExitAllMenus → ReloadTilesetAndPalettes → RefreshSprites`에는 맵 스프라이트 재로딩이 있고, 팔로잉 토게피가 선택되면 같은 잘못된 뱅크를 읽을 가능성이 있다. 부화 후 파티 메뉴 역시 그 아이콘을 로딩한다.
- 기본 별명은 `CopyDefaultPokemonName`으로 11바이트 저장 레코드에 복사한다. 현재 발견한 근거만으로 한글 이름 처리 자체를 부화 정지 원인이라고 판단하지 않는다.
- 균열/껍질 조각은 공용 스프라이트 애니메이션을 사용한다. 균열 전후의 레지스터, 스택, 데이터 인덱스, 디버그 생성 알의 구조가 다음 조사 대상이다.

유력한 원인 후보와 한계:

1. **문제 ②의 잘못된 토게피 아이콘/팔로잉 뱅크**: 부화 후 파티/맵 복귀 실패를 설명할 수 있다. 그러나 자연 부화에서 관찰한 실제 중단 시점과 포켓몬의 파티 위치가 확인되지 않았으므로 이 후보만으로 전체 증상을 확정하지 않는다.
2. **부화 애니메이션 또는 부화 데이터 전환의 별도 결함**: 자연 경로에서 맵 복귀 이전에 실패한다면 별도로 추적한다. 현재 특정 명령의 오동작은 아직 확인하지 못했다.

수정 계획:

1. 우선 ②의 명백한 배치 결함을 제거하여 아이콘/팔로잉 경로를 정상화한다.
2. 자연 부화 및 실제 디버그 진입 경로의 데이터·호출 규약을 비교한다. 알 종족, party species, happiness, HP/DV, 저장 이름 길이, 스택 균형 및 뱅크 복원을 정적 검증한다.
3. 균열 시작부터 조각 종료와 맵 복귀까지 공용 sprite state/WRAM/VRAM writer를 조사한다. 원인이 특정된 지점만 수정한다.
4. 부화 애니메이션을 생략하거나, 무조건 닉네임을 바꾸거나, 임의 딜레이를 넣는 수정은 하지 않는다.
5. 정적으로 별도 결함을 특정하지 못하면 부화 코드를 추측 수정하지 않는다. 확인된 수정들을 완료한 뒤 마지막 실행 검증에서 실패 위치를 좁힌다. 이 경우 ⑤는 미해결로 남기고 추가 계획을 설명한다.

예상 수정 파일: 별도 결함 확인 시 `engine/pokemon/breeding.asm` 또는 확인된 실제 소비자. ②만으로 끝날 가능성도 있으며, 현 시점에서 부화 코드 변경은 확정하지 않는다.

## 4. 빌드·정적 검증

- 일반/디버그의 소스 및 생성 자산을 일치시켜 빌드한다. ROM0 배치, ROMX 뱅크 상한, 링크 경고, ROM 헤더와 체크섬을 확인한다.
- 포인터 테이블과 ROM 실제 바이트를 비교한다. 압축 결과 크기, 두 프레임의 소스 오프셋, 6개 파티 슬롯, 소지품·메일·안농 분기를 점검한다.
- 상태창/배틀 VRAM 구간을 writer와 복원 범위에 대응시킨다. 특히 `$31–$54`, `$42–$53`, 한글 캐시 `$80–$eb`를 구분한다.
- 분홍→초록→파랑→분홍, 역방향 전환 각각의 속성맵 결과를 확인한다. HP·경험치·포켓몬·페이지 아이콘 팔레트를 보존한다.
- 부화 경로의 데이터 필드, 저장 이름 크기, 레지스터 보존, 루프 종료, 뱅크 전환을 확인한다.
- 사용자 기술 이름 파일의 해시 및 관련 없는 diff를 확인한다. 기존 작업 내용을 되돌리지 않는다.
- 이번 분석 단계에서는 신규 빌드를 수행하지 않았다. 현존 ROM/심벌의 검증은 신규 수정 후 빌드 성공 증거가 아니다.

## 5. 모든 수정 후 사용자 실행 테스트

실행 테스트가 끝나기 전에는 ‘완전히 해결’로 판정하지 않는다. 새 ROM을 부팅해 확인하며, 과거 ROM의 실행 중간 세이브 스테이트를 그대로 이어 쓰지 않는다. 기존 `.sav`는 보존한다.

1. 배틀에서 세 페이지를 방문한 뒤 파티 메뉴와 배틀로 복귀. 다른 포켓몬 선택, 반복 진입, 대타/작아지기 상태도 확인. 뒷모습·상대·문자·HP·경험치 바에 잔상 없음.
2. 통통코를 파티 1번과 6번에 놓고 아이콘 두 프레임, 선택/비선택, 소지품/메일 여부를 확인. 토게피와 같은 섹션의 다른 종, 해당 섹션 밖의 정상 종도 비교. 맵 팔로잉 그래픽도 확인.
3. 한글 대화·다른 메뉴를 거친 상태 및 새 부팅에서 NO./ID 기호 확인. 포켓몬과 페이지를 여러 번 바꾸어도 기호가 바뀌지 않음.
4. 세 페이지를 정방향·역방향으로 전환. 프레임 안쪽 배경은 해당 페이지와 같고 HP·경험치 바 고유 색은 유지됨.
5. 토게피 자연 부화와 사용한 디버그 경로를 각각 확인. 가능하면 다른 종의 알도 확인. 균열/껍질 조각/포켓몬 등장/울음/별명 예·아니오/맵 복귀/파티 메뉴/상태보기/저장 후 재시작까지 연결.
6. ⑤가 남으면 마지막 정상 화면과 실제 중단 단계만 추가 기록한다. 에뮬레이터 디버거가 예외로 정지한 경우와 게임 자체 무응답/종료를 구분한다.

## 6. 승인 지점

이 계획은 **구현 승인을 받기 전에는 실행하지 않는다**.
우선 ②의 지원 범위 밖 뱅크 배치를 수정하고, ⑤를 별도 검증한 뒤 나머지 확인된 결함을 한 문제씩 수정하는 순서다.
부화의 모든 증상이 한 원인이라고 확정하지 않았으며, 코드 조사만으로 실행 성공을 주장하지 않는다.

## 7. 승인 후 후속 작업 기록 (2026-10-10)

사용자 승인: “응, 진행가능. 시작하자.” 스킬 활용 및 지속 검증도 요청했다.
기존 사용자 변경을 보존하며 별도 에뮬레이터 실행이나 세이브 편집은 하지 않는다.

### 소스 변경

- ② `PokemonSprites5`를 통통코 앞에서 두 section으로 분할했다. 9개 동행
  그래픽 section 모두에 MBC3 bank `$7f` 상한 assertion을 넣었다. 포인터와
  그래픽 내용은 그대로이며 통통코만의 예외 처리나 mapper 변경은 없다.
- ⑤ 부화 카운터, party species 갱신, HP/OT/이름 처리, 균열과 10개 껍질
  조각의 슬롯/종료, 애니메이션 bank, 메뉴/동행 복귀를 추가 조사했다.
  별도 결함을 특정하지 못해 `breeding.asm`은 수정하지 않았다. ②가 부화 후
  아이콘/동행 소비자에도 적용되지만 자연 부화 정지 해결 여부는 미확정이다.
- ① 배틀 그래픽 백업/복원을 `$00–$54` 전체로 확장했다. 첫 36타일은 뒷모습,
  다음 49타일은 정면 그림이다. 백업은 `$8000–$854f`로 캐시 `$8800` 이전에
  끝난다. LCD를 끈 상태에서 bank 0을 선택하고 호출자의 VRAM bank를 복원한다.
- ③ 번호 마침표와 같은 직접 참조를 하던 포케러스 면역 점을 공통 상태창
  루틴으로 출력한다. CGB는 `FarCall_de`로 좌표를 보존하여 `_PlaceHangul`의
  일반 문자 경로를 이용한다. DMG는 고정 타일을 유지하고 위 행을 쓰지 않는다.
  고정 `№` 글리프와 숫자 위치, ID 문자열 출력은 유지한다.
- ④ 상태창의 세 프레임만 `TextboxBorder`로 바꿨다. 페이지마다 오른쪽
  `(8,0)`부터 12×18 속성을 팔레트 0으로 구성하고 분홍의 `(9,16)` 10칸만
  경험치 팔레트 2로 지정한다. 왼쪽/구분선 속성과 전역 `Textbox`는 보존한다.
  CGB에서 페이지 팔레트 적용 후 `ApplyAttrmap`으로 속성맵을 전송한다.
- 검증 도구 `tools/verify_following_sprites.py`와
  `tools/verify_stats_transitions.py`를 추가했다. `.verification/`는 기존 ROM,
  중간 산출물 및 로그를 보관하는 로컬 디렉터리로 Git에서 제외했다.

### 현재 검증 범위

수정 과정의 디버그 조립은 통과했다. 기존 `std_text.asm:155`의 `~` 경고는
별도 과제로 보존했다. 아이콘 수정만 반영한 중간 디버그 링크/후처리에서는
ROM이 2 MiB로 줄고 모든 ROMX 심벌이 `$7f` 이내에 들어왔다. 278개 PNG 크기,
원본/압축/ROM 바이트/포인터/두 아이콘 프레임 검증을 최종 빌드에서 다시 한다.

### 통합 빌드에서 발견한 폰트 재생성 결함

`make -B`로 전체 그래픽을 재생성한 뒤 이전 정상 ROM과 비교하니 한글 폰트가
달라졌다. `font_hangul.png`는 128×2816의 8×16 글자 배열인데 기존 catch-all
규칙은 8×8 타일 행 순서로 생성한다. 출력기는 각 글자의 위/아래 타일을
연속해서 읽으므로 일반 변환만으로는 기존 폰트를 재현할 수 없었다.

원본 PNG를 글자 단위로 재배열하면 이전 ROM의 한글 폰트 45,056바이트와
전부 일치했다. `Makefile`에 해당 폰트만 기존 `tools/gfx --interleave --png`
후처리를 적용하는 규칙을 추가하고 폰트 및 의존 객체를 다시 빌드했다.
PNG나 문자표, 폰트 그림을 바꾸거나 이전 ROM에서 추출한 폰트를 빌드 입력으로
사용하지 않았다. 검증 도구는 PNG를 독립적으로 읽어 2,816개 8×16 글자의
바이트 순서와 최종 ROM의 네 폰트 segment를 비교한다.

### 최종 검증 결과

- 기존 Makefile에서 `make -B -j2 RGBDS=rgbds-1.0.0/ crystal crystal_debug`
  성공: 도구·파생 그래픽 재생성, 일반/디버그 각각 18개 객체 조립, 링크,
  RGBFIX와 Stadium 후처리. 폰트 규칙 보완 뒤에는
  `make -j2 -W gfx/font/font_hangul.png RGBDS=rgbds-1.0.0/ crystal crystal_debug`
  로 폰트와 의존 객체를 다시 생성하고 두 ROM을 재링크/후처리했다.
- 일반·디버그 모두 2 MiB, MBC3+RTC 헤더 `$10/$06/$03`, 헤더/전체 체크섬
  통과. 전체 ROMX 주소가 `$01–$7f` 이내다. ROM0 여유는 각각 60/67바이트다.
- 통통코는 일반 `$20:$63bc`, 디버그 `$20:$63c9`; 토게피는 두 빌드 모두
  `$0b:$74ac`. 기존 디버그의 `$80` 스프라이트 section은 없어졌다.
- 두 ROM 각각 동행 자료 278개의 PNG 크기, 24타일 크기, 포인터, 압축 왕복,
  최종 ROM 바이트, 아이콘 두 프레임 검사 통과. 압축 검사기는 7개 명령 및
  긴 명령/상대 참조/잘못된 입력을 독립 fixture로 점검한다.
- 최종 ROM의 수정된 SM83 명령을 제한된 harness로 검사했다. 두 VRAM-bank
  진입의 배틀 복원, CGB 페이지/flag 조합 45개와 DMG 속성 보존 1개,
  CGB/DMG의 두 좌표에서 점 출력 4개 모두 통과했다. 실제 소비자에서 새
  점/프레임/속성 초기화/속성 전송 루틴을 호출하는 명령도 확인했다.
  외부 함수는 계약을 모형화하므로 실제 실행·타이밍·시각 검증은 아니다.
- 같은 harness로 수정 전 ROM의 `$42–$54` 복원 누락을 재현했다.
- 일반 15,637개, 디버그 15,688개 RAM/VRAM 계열 심벌의 주소와 bank 변경
  0개. 기존 한글 폰트 45,056바이트 및 일반/배틀 폰트가 이전 ROM과 동일하다.
- `data/moves/names.asm` SHA-256은 최초 기록과 동일하다. 기술 이름이나
  기존 세이브는 수정하지 않았다. `git diff --check`도 통과했다.

### 남은 실행 검증과 ⑤의 상태

에뮬레이터 테스트는 수행하지 않았다. 위 §5의 최종 테스트를 사용자가 직접
진행한다. 특히 토게피 자연 부화와 실제 사용한 디버그 경로를 분리하고,
부화 애니메이션 → 별명 선택 → 맵/동행 복귀 → 파티/상태보기까지 확인한다.
기존 `.sav`는 보존하며 이전 ROM의 실행 중간 save state를 검증 근거로
사용하지 않는다.

①~④는 코드 수정과 정적 검증을 완료했지만 실제 증상 해소 판정은 대기다.
⑤는 공통 후보인 뱅크 배치를 수정했을 뿐, 자연 부화 정지의 별도 원인을
확정하거나 해결했다고 기록하지 않는다. 부화가 계속 실패하면 최종 정상
단계와 실제 중단 위치를 근거로 다음 진단을 진행한다.
