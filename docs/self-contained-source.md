# Crystal 소스 독립성 수정

2026-10-09. Crystal 저장소를 단독으로 복원하고 빌드할 수 있어야 한다.
Gold와 OldGold는 이식·비교를 위한 참고 자료이며 제품 빌드 입력이 아니다.

## 변경 범위

기존 `data/pokemon/names.asm`은 다음 외부 파일을 직접 포함했다.

- `../oldgold/constants/charmap_hangul.asm`
- `../oldgold/data/pokemon/names.asm`

이 두 참조를 제거했다. 251종과 특수 슬롯을 포함한 256개 이름 엔트리는
Crystal의 `data/pokemon/names.asm`에 직접 보관한다. 이름용 2바이트 한글
문자표는 `constants/charmap_pokemon_names.asm`에 보관한다. OldGold에서
이식한 정확한 이름·문자 코드를 출발점으로 삼았으며 앞으로 Crystal에서
독립적으로 관리한다. 별도 복사·동기화 과정은 빌드에 필요하지 않다.

이름은 기존처럼 엔트리당 10바이트를 사용한다. `GetPokemonName`이
packed 이름을 일반 대화 인코딩으로 확장하는 처리와 종 상수·도감 순서는
그대로다. 일반 대화 문자표와 packed 이름 문자표는 서로 다른 인코딩이다.

## 조사 범위

ASM의 INCLUDE/INCBIN, Makefile과 보조 빌드 파일, 도구 소스·스크립트,
CI 설정을 대상으로 상위 폴더 참조, 절대 로컬 경로, 외부 프로젝트 이름을
조사한다. Git의 심볼릭 링크·서브모듈도 확인한다. 문서의 출처 표기와 게임
데이터에 남아 있는 원작 모바일 서비스 주소는 로컬 소스 의존성과 구분한다.

RGBDS 1.0.0, make, C 컴파일러와 빌드에 쓰는 시스템 라이브러리는 설치형
도구 의존성이다. `INSTALL.md`와 `.rgbds-version`이 해당 설치 조건을
관리한다. 로컬 `rgbds-1.0.0` 실행 파일을 Git에 넣을 필요는 없다.

## 검증

수정 전 외부 참조를 사용하는 main 객체와 수정 후 내부 소스를 사용하는
main 객체를 일반·디버그 설정으로 각각 조립하고, 같은 나머지 객체와 링크해
ROM 데이터의 동일성을 비교한다. 기존 객체가 현재 소스보다 오래된 경우
해당 객체를 현재 소스로 조립해 양쪽 비교에 동일하게 적용한다.

별도 검증 폴더에는 Git에서 관리하는 Crystal 소스와 이번 추가 파일만
복사한다. 이 폴더의 상위에는 Gold/OldGold가 없고 기존 객체·ROM·변환된
그래픽도 없다. 이 상태의 새 빌드는 외부 프로젝트뿐 아니라 미보관된 로컬
파일에 의존하는 문제도 확인한다. 검증 결과와 제한은 작업 완료 시 아래에
기록한다.

### 확인된 결과

- 이름 256개 엔트리의 문자열과 순서가 이전 소스와 일치한다.
- ASM 3,029개 파일의 직접 INCLUDE/INCBIN 경로가 Crystal 루트 내부로
  해석된다. 빌드 파일·도구·CI에서 추가 게임 프로젝트 의존성을 찾지 못했다.
- Git에 등록된 심볼릭 링크와 서브모듈은 없다.
- 수정 전/후 링크된 일반 ROM 데이터의 SHA-256은 모두
  `a96f93395d832976d7ec71e625dd993dbf1108ae3ad1026445e4aba001ced250`이다.
- 수정 전/후 링크된 디버그 ROM 데이터의 SHA-256은 모두
  `e99b49a2c7bb873dc756754f9ed16e7a54bc32a5537df8b335d02c89e5d70c67`이다.
- 위 비교는 rgbfix/stadium 후처리 전의 동일 조건 링크 결과이며, 새 빌드의
  최종 산출물 해시와 혼동하지 않는다. 현재 RAM 소스와 오래된 기존 객체의
  불일치가 있어 RAM 객체를 새로 조립한 뒤 양쪽 비교에 동일하게 적용했다.
- 에뮬레이터 실행은 별도로 수행하지 않았다. 이번 변경의 실행 동작 보존
  근거는 일반·디버그 ROM 데이터의 바이트 동일성이다.

### 독립 소스 빌드 결과

Git 관리 소스 4,925개와 추가 문자표만 넣은 복사본에서 모든 그래픽과
일반·디버그 객체를 새로 생성했다. Gold/OldGold, 기존 객체, 기존 ROM,
기존 변환 그래픽을 복사하지 않았다. 도구는 설치된 RGBDS 1.0.0과
Cygwin make/gcc를 사용했다.

- 디버그 ROM `pokecrystal_debug.gbc`가 생성됐다(4,194,304바이트).
  최종 SHA-256:
  `9f1f02874b2ed3160a1d44b596596a7d448fbe1219b270d6057c20db1df99d91`.
  헤더 체크섬과 전체 ROM 체크섬을 확인했고, Makefile의 rgbfix/stadium
  후처리를 다시 실행해도 최종 파일 해시는 같았다.
- 일반 ROM은 `RAM Name Display Home`을 ROM0에 배치하지 못해 최종
  링크에 실패했다. 소스/그래픽 생성에서 외부 파일 누락은 없었다.
- 새로 생성한 나머지 객체에 수정 전 이름 소스의 main 객체를 적용해도
  일반 링크는 같은 오류로 실패하고 디버그 링크는 성공했다. 일반 버전의
  공간 부족은 이번 이름 소스 내부화가 만든 문제가 아니다. 오래된 객체를
  이용한 전후 비교와 완전한 새 빌드 결과를 구분해야 한다.
- 따라서 **디버그 빌드의 단독 소스 복원**은 확인했다. 일반 빌드의 최종
  성공은 별도 ROM0 공간 수정이 필요하며, 이번 작업에서 그 게임 코드까지
  변경하지 않았다.

새 문자표와 이 기록을 포함한 추가 소스도 수정 파일과 함께 Git에 보관해야
단독 복원이 가능하다. OldGold의 후속 수정은 Crystal 소스에 자동 반영되지
않는다.
