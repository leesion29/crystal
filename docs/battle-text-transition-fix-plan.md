# 전투 이름·빈 기술·파티 상태·포획 도감 표시 수정

## 기준 및 사용자 관측 (2026-10-10)

- 일반 닉네임 및 기본 치코리타 이름 테스트는 사용자 통과.
- 드문 입력 글자 조합은 원본 한글판의 입력 범위를 유지한다는 사용자 판단으로
  이번 수정에서 입력 자모/지원 음절을 확대하지 않는다.
- 야생 출현/포획/쓰러짐의 적 이름은 깨지지만 공격 대사의 이름은 정상.
- 포획 도감 하단에 작은 문자 조각이 남는다.
- 화면 왕복 후 빈 기술의 `-`가 다른 글자 또는 빈칸으로 보인다.
- 파티 목록에 이름처럼 보이는 다른 글자가 섞인다. 첨부에서는 기절한
  첫 개체의 상태 표시 위치에 글자가 나타난다.
- 라디오는 개선되었지만 넘침이 남아 있다. 이번 전투/메뉴 수정으로
  라디오까지 해결됐다고 주장하지 않는다.

## 원인별 계획

1. 압축 이름을 받는 대사를 소비자 경계에서 디코딩한다.
   `text_ram wEnemyMonNickname`/`wBattleMonNickname`은 일반 문자열 경로다.
   기존 `text_buffer 5`/`6`은 같은 이름 레코드를 디코더로 출력한다.
   공격 대사의 USER/TARGET 디코더와 일치시킨다. 문구/번역은 변경하지 않는다.
   버퍼 주소 판별을 ROM0에 추가하는 대신 해당 텍스트 명령만 교체한다.
2. 빈 기술의 `-`는 글리프 캐시를 우회하는 타일 직접 쓰기를 중단한다.
   한글 기술 목록과 일반 ListMoves 둘 다 `PlaceString` 경로로 출력한다.
   기존 좌표, 행 간격, 빈 칸 개수는 유지한다.
3. 파티 상태의 FNT/PSN/BRN/FRZ/PAR/SLP도 고정 타일 번호를 찍는다.
   한글 캐시와 타일 수명이 충돌할 수 있으므로 기존 세 글자 문자열을
   PlaceString으로 출력한다. 기존 CopyStatusString의 HL/DE 진행량을 유지한다.
   이 수정은 상태 문구를 번역하거나 파티 레이아웃을 바꾸지 않는다.
   상태가 정상인 개체의 실제 이름도 깨진다면 별도 원인을 조사한다.
4. 포획 도감은 상세 화면을 그려 메뉴의 두 행을 만든 뒤 행 17만 지운다.
   포획 화면에서는 메뉴 윗부분이 차지하던 행 16의 하단 테두리를 복원하고,
   행 17은 기존 포획 화면의 비어 있는 검은 바를 유지한다.
   일반 도감의 분포/울음소리 메뉴는 그대로 둔다.

## 검증과 변경 제한

- 기존 미커밋 변경, 그래픽 PNG, 대사 문구, 세이브를 보존한다.
- 디버그 조립/프로젝트 layout.link 링크, diff 검사 및 RAM 심볼 주소 비교.
- 소스에서 두 닉네임 버퍼를 일반 text_ram으로 출력하는 명령이 남는지 확인.
- 사용자가 실제 화면을 재현하기 전에는 런타임 해결로 닫지 않는다.
- 일반 ROM의 기존 ROM0 공간 부족 문제는 별도 제한이다.

## 사용자 재검증 순서

1. 구구/꼬렛/꼬리선 출현 → 공격 → 쓰러뜨림의 이름을 비교한다.
2. 아직 잡지 않은 구구 포획 → 도감 하단 → 닉네임 질문을 확인한다.
   일반 도감에서는 분포/울음소리 메뉴가 남아 있어야 한다.
3. 기술 두 개인 개체로 기술 선택 → B → 파티 능력치 화면 → 전투 복귀 →
   기술 선택을 3회 반복한다. 빈 두 칸은 계속 `-`여야 한다.
4. 기절/정상 개체를 함께 둔 파티에서 능력치 화면 왕복을 3회 반복한다.
   이름 줄은 유지되고 상태 표시는 자기 위치에서만 나와야 한다.
5. 기존 통과 닉네임 `쁘`, `가나다라마`, `가쁘가쁘가`를 전투에서 회귀 확인한다.
   이 빌드 결과와 이전 빌드의 라디오/지역 이름 결과를 구분해 기록한다.

## 구현 및 정적 검사 결과

- battle.asm/common_1.asm/common_3.asm의 이름 직접 출력 명령 25개를
  text_buffer 5/6으로 변경했다. 기존 두 닉네임 버퍼를 text_ram으로 읽는
  명령은 data/engine 범위에서 남아 있지 않다. 대사 문구는 그대로다.
- BattleListMoves/ListMoves의 빈 기술 표시는 `-@`를 PlaceString으로 그린다.
  PlaceString은 HL을 보존하므로 기존 다음 행 계산을 유지한다.
- CopyStatusString은 세 글자 문자열을 캐시 경로로 그리고, 기존 함수처럼
  HL/DE를 입력 위치에서 두 바이트 진행한 위치로 반환한다.
- 포획 도감에서 행 16의 x=1..19를 원래 테두리 타일 $39로 복원한다.
  메뉴의 윗부분은 x=4..16에 있으므로 전부 덮인다. 행 17은 기존 검은 바이며
  일반 상세 화면의 메뉴 생성 함수 자체는 변경하지 않았다.
- 일반/디버그의 변경된 main/common 조립과 디버그 링크 통과.
  검사용 링크는 `.verification/check.*`이며 사용자 ROM/세이브를 덮어쓰지 않았다.
- 현재 사용자 디버그 심볼과 RAM 심볼 14,464개를 비교하여 주소 변경 0개.
- git diff --check 통과. 기존 std_text.asm:155의 `~` 경고는 남아 있다.
- 실제 화면 왕복/포획 재현은 사용자 검증 대기다. 간헐적인 이름 자체 손상,
  다른 상태 표시 위치 또는 라디오 넘침까지 해결됐다고 주장하지 않는다.

## 사용자 후속 확인 및 보류 방향

2026-10-10 사용자 보고: 이번 수정은 잘 동작한다. 첨부 파티 화면의
기절 상태 `FNT`도 다른 한글 타일로 바뀌지 않고 정상 표시된다.
개별 검증 경로별 결과는 별도로 제공되지 않았으므로 모든 경로의
상세 런타임 검증 완료로 확대하지 않는다.

- 영문/한글 길이 차이에 따른 잘림과 레이아웃 조정은 나중에 진행한다.
- 체력바는 개조 버전의 디자인이므로 한글판 원본과 다르다는 이유로 바꾸지 않는다.
- 향후 기절 표시는 첨부 한글판처럼 `기절` 문구를 사용하는 방식을 참고한다.
  이번 요청은 참고 방향 기록이며, FNT 문구/좌표/체력바를 지금 변경하지 않는다.
- 라디오 넘침의 해결 여부는 이번 통과 보고로 확정하지 않는다.
